# gateway —— 门与索引

> 一扇门搜全库：**只回指针 + 逐字片段，不做转述。**
> 它是整套记忆的**入口** —— 账本建的是一手材料，这个负责把它们取回来。

---

## 它防的是什么

**「存下来了，但取不回来」——以及更坏的：「取回来了，但是别人转述的」。**

```
✗ 只有存储没有索引   → 你知道它在那儿，但你不知道在哪
✗ 用摘要回答        → 二手污染。摘要说「他当时不同意」，
                      原文说的是「这个方向先放一放」—— 差的不是措辞，是事实
✗ 猜一个地址        → ★ 错的门牌比没有门牌更坏（见下）
```

> ### ★ 所以这个工具只有一条输出形式：**指针 + 逐字片段。**
> 它从不告诉你「大概是什么意思」，只告诉你「原文在这、原话是这个」。

---

## 三分钟上手

```bash
# ① 先建索引（这东西的前提）
node index.mjs
#    ★ 验：同级出现 index/ 目录，里面有几份 json

# ② 现在是什么时候、距上一轮多久、有没有欠着的活
node query.mjs now
#    ★ 验：一行时钟 + 未结条数

# ③ 搜一个词
node query.mjs 某个词
#    ★ 验：出来的是【指针 + 逐字片段】，不是转述

# ④ 用指针回原文
node query.mjs open <上一步给出的指针>
#    ★ 验：打印那一段原文
```

---

## 两种地址

```
log:<会话ID>#seq=<n>      会话日志里的第 n 条（逐字原话）
ledger:<ISO 时间>          账本里的某条记录
```

**★ 它们是**可解析的**，不是给人看的标签** —— `open` 直接认它们。

---

## ★ 一条纪律（这条比功能重要）

> **拿不到精确地址时，写「未知」并给一个检索入口，绝不猜。**

**理由**：错的地址**比没有地址危害更大** ——
它会返回错误内容，**而且在形式上与正确结果无法区分。**
被一个错误地址骗一次，你会开始怀疑所有地址。

**所以这个工具的失败方式是「我不知道」**，不是「大概是这个」。

---

## 它搜哪几层

```
L2  账本              （ledger.jsonl）
L3  一手层            工作区里的 markdown
L4  索引              会话日志的摘要索引（index.mjs 建出来的）
    留底库            更早的归档
```

**★ 输出里 `[一手]` / `[索引]` / `[程序]` 分得清清楚楚** ——
**你不会把「摘要」误当成「原话」。** 这一条是它存在的理由的一半。

---

## 两个文件

```
query.mjs          门：搜全库、回指针、开原文
index.mjs          索引构建器：把会话日志压成带指针的摘要
session-store.mjs  读会话日志（多帧压缩格式，需要专用读取）
```

**★ 为什么索引要单独一个程序**：全量索引跑一次要几秒到几十秒，
而**查询必须快**。所以读和建分开 —— 建的时候慢一次，查的时候一直快。

---

## 边界

```
✗ 不转述 —— 只回指针与逐字片段
✗ 不猜地址 —— 拿不到就写「未知」
✗ 不联网 —— 全在本机
✗ 不改任何东西 —— 纯读（写是 ledger 的事）
```
